# 計時以不受系統時間調動影響的時鐘計算

使用者於 2026-11-11 確認：系統時間被手動調動或自動校正時，計時照常倒數，不暫停、不提示。原本剩餘時間是「結束時刻 − 系統時間」，時間往回調會讓剩餘時間超過長度、恢復點無法保存，往前調則把跳過的時間算進專注長度。

- 計時、恢復點檢查、復原期限、閒置歸零與完成摘要的「現在」，改由 App 啟動時的系統時間加上之後經過的單調時間推算。單調時間取自 `ContinuousClock`：不受手動改時間影響，睡眠期間照常前進，所以 ADR-0002「睡眠照常倒數」不變。
- 面向使用者與資料的時刻，在輸出時換算成目前的系統時間：完成紀錄與恢復點的開始時刻、畫面上的結束時刻、復原膠囊的倒數與到點提醒的排程。開始時刻因此是這一段實際開始的那一刻，以目前的系統時間表示；系統時間校正後，統計依校正後的日期歸屬。讀回恢復點時反向換算。
- 系統時間變更時重排到點提醒與畫面的刷新節拍：節拍以系統時間排格線，往回撥時已排的格線落在未來，畫面會停住。編輯紀錄時「不得晚於現在」的檢查與統計的「今天」仍用系統時間。
- 不另存單調時間：重新開啟後從新的系統時間起算，恢復點本來就只存暫停狀態與剩餘秒數。

## 實測依據

2026-11-11 在 macOS 27.0.1 每 2 秒記錄系統時間、`ContinuousClock` 與 `SuspendingClock`：手動把系統時間往後調約 1 小時再調回，兩個單調時鐘都只前進 2 秒；睡眠約 19 秒期間，系統時間與 `ContinuousClock` 都前進 18.1 秒，`SuspendingClock` 只前進 2 秒。紀錄見本機 #63。長時間睡眠未測。

## Considered Options

- 偵測到跳動時自動暫停並排除跳動的那段：要分辨睡眠與跳動，使用者會看到計時被停下並需要說明。
- 以 `SuspendingClock` 或 `mach_absolute_time` 計算：睡眠時不前進，違反 ADR-0002。
- 計時閒置時把起點重新對齊系統時間：對齊前後算出的閒置、摘要與復原期限會跟著跳，仍需輸出時換算才完整，不如一律換算。
