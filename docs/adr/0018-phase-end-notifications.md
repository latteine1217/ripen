# 階段結束的系統通知由使用者開啟

2026-11-05 決定：階段倒數到 0 時可以傳送系統通知，預設關閉，由設定開啟。靜音、正在全螢幕工作或視窗被蓋住時，提示音與閃色動畫都可能被錯過。

- 與提示音共用同一個提醒出口：每段只送一次，鎖定或睡眠中延到回來才送（ADR-0002）。到點才送，不預先排程，計時只有一個來源。
- 開啟時才請求權限，既有使用者不會突然看到權限提示。設定只存意願，權限向系統讀取，使用者在系統設定改動後開關跟著變。
- 內容只有階段與下一步，不含分類名稱，避免在畫面分享時露出。
- 通知不發聲，聲音由提示音負責；Ripen 在前景時不顯示橫幅。
- 點通知把 Ripen 帶到前景，不切換形態。離開超時（按完成）時移除通知中心裡的舊通知；同時只保留一則。
- 通知上不放「完成」按鈕：要先處理與 5 秒復原的互動，第一版不做。

權限提示以通知的形式出現在螢幕右上角，容易錯過，也可能一直等著。等待期間設定裡說明提示在哪；途中關掉開關，之後才按允許也維持關閉。

## ad-hoc 簽章

2026-11-05 在 macOS 27.0.1 實測：ad-hoc 簽章的 App 從 `~/Applications` 執行可以取得權限並顯示橫幅。同一個 App 從 `/private/tmp` 執行時，權限還沒決定就回 `UNErrorDomain Code=1`，不出現提示；這種情況開關維持關閉並提示到系統設定。使用者拒絕過再請求也回同一個錯誤。

## Considered Options

- 預設開啟、第一次開始專注時請求：比較容易被發現，但會打斷第一次使用，既有使用者也會突然被詢問。
- 只加強提示音：解決不了靜音的情境。

## 驗收

單元測試涵蓋開關、只送一次、離開後才送、完成時移除、復原不重送與權限狀態。真視窗、權限被拒與點擊由發行驗收清單的 B 層確認。升級後權限是否保留，要在第一個含此功能的版本更新到下一版時實測：ad-hoc 簽章每版都會變。
