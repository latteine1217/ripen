# 刪除分類時，紀錄改為未分類

使用者於 2026-10-30 確認：分類可以刪除，入口在分類詳細頁。刪除後該分類的完成的專注全部改為未分類，時間、次數與統計都保留；刪除前以確認對話框說明有幾次專注會改為未分類，刪除後不能復原。

- 資料庫在同一個交易內把該分類紀錄的 `project_id` 設為 NULL，再刪除分類。資料表結構不變，欄位語意不變，符合 ADR-0007；資料中不留下指向不存在分類的識別碼。
- 寫入失敗時，刪除與其他未保存的變更一樣保留重試，退出前視為未保存；重試前重新讀取歷史時先套用刪除，已刪除的分類不會因讀回舊資料而復活。
- 還能復原與尚未寫入的紀錄一併改為未分類。進行中的專注、下次的選擇、完成摘要與成果卡入口指向它的，也改為未分類；從懸浮窗或瀏海島開著的該分類成果卡隨之關閉。
- 刪除不提供復原膠囊：GLOSSARY 的復原只涵蓋跳過、重設與完成。復原會換回的摘要或入口指向被刪的分類時，復原機會隨之結束，暫存的完成照常寫入。

## Considered Options

- 連同紀錄一起刪除：會失去已投入的專注時間，與「未分類同樣保留紀錄並計入統計」衝突。
- 封存：分類從選單與列表隱藏、紀錄仍歸屬它，之後可以恢復。這是另一個功能，需要新的資料欄位與恢復入口。
- 只刪除分類、紀錄保留舊識別碼，讀取時再解析為未分類：資料中會長期留著懸空的識別碼，每個彙總都要記得解析。
