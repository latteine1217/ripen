# 以作者簽章驗證 App 內更新

2026-11-05 決定：App 內更新改以作者的 Ed25519 簽章驗證 dmg，取代 ADR-0009 中比對 GitHub SHA-256 的做法。

Ripen 不使用付費的 Developer ID（只有 ad-hoc 簽章），而 GitHub 回傳的雜湊與 dmg 同源：GitHub 帳號或 Release 遭竄改時，比對雜湊擋不住，通過後 App 還會移除隔離屬性並安裝。簽章讓「這是作者發行的」不再依賴 GitHub。

- App 內建公鑰（`Ripen/Update/UpdateSigningKey.swift`）；發行時以 `scripts/update-signing.swift sign` 簽 dmg，並將 `Ripen-<版本>.dmg.sig` 與 dmg 一起上傳。
- 私鑰只在作者的鑰匙圈與密碼管理器的備份，不進 repo 與 CI。
- 沒有簽章檔、簽章無效或格式錯誤一律不安裝，改提供下載頁。不退回其他檢查，否則刪掉簽章檔就能繞過。
- 簽章涵蓋的是 dmg 內容，不含版本號；把舊版 dmg 改名成新標籤會被既有的「dmg 內 App 版本須與標籤一致」擋下。
- 簽章已涵蓋內容，App 不再比對 GitHub 雜湊。bundle id、版本與 `codesign` 檢查保留。舊版 App 只看 dmg 附件，不受多一個 `.sig` 影響。

## 保護範圍

只保護 App 內更新。首次下載與 Homebrew 仍信任 GitHub（tap 也在同一個帳號下）。第一個內建公鑰的版本本身，仍由舊版以雜湊比對取得；從它之後的更新才受簽章保護。

## 金鑰遺失或外洩

發佈內建公鑰的版本後，之後每一版都必須用同一把私鑰簽。私鑰遺失時，已安裝的版本無法再透過 App 內更新取得新版；外洩時要立刻停發並公告。兩者都由使用者手動下載內建新公鑰的版本解決。

## Considered Options

- Developer ID 與公證：#26 已決定不採用。
- Sparkle 2：EdDSA 簽章相同，但要新增依賴並維護 appcast；只為驗證不值得。
- 內建多把公鑰以便輪替：目前只有一位發行者，遺失時走手動下載即可，不為此增加複雜度。

## 驗收

單元測試涵蓋有效簽章、內容被改、其他金鑰的簽章、缺簽章、格式錯誤與沒有內建公鑰，後五種都不得安裝。完整更新流程由發行驗收清單的 A 層實機確認；第一次真正走簽章路徑的是從第一個內建公鑰的版本更新到下一版。
