# 只在使用者要求時檢查更新，驗證後才安裝

2026-10-29 決定：不做自動更新，但設定可以手動檢查；有新版時要能直接下載安裝。

- 只有按下「檢查更新⋯」（App 選單或設定「關於」區塊）時才連網，向 GitHub 查詢最新的正式版（排除 draft 與 prerelease）。其他時候不連網，README「本機與隱私」據此改寫。
- 有新版時只顯示版本與版本說明連結；按「下載並安裝」才下載。
- Ripen 只有 ad-hoc 簽章，無法以開發者身分驗證來源，因此以 GitHub 為附件算出的 SHA-256 核對下載內容；接著確認 dmg 中 App 的 bundle id、版本與 Release 標籤一致，並以 `codesign --verify` 確認簽章後未被改動。缺少雜湊或任何一項不符就不安裝，改提供下載頁。
- 換新由背景 shell 在 App 結束後執行：舊版先改名備份，複製新版成功才刪除備份，失敗則放回舊版，最後重新開啟。結束走一般流程，超時中的專注照常記錄、未保存紀錄照常詢問；取消退出時，更新延到下次結束。
- App 不在可寫入的位置（從 dmg 執行、被系統搬移、沒有寫入權限）時不嘗試提權，改在 Finder 打開下載的 dmg，請使用者自己拖到「應用程式」。

## Considered Options

- Sparkle 2：成熟、可自動安裝，但需要新增依賴、保管 EdDSA 私鑰並維護 appcast；ad-hoc 簽章下的更新行為也需另外驗證。等有 Developer ID 與公證後再評估。
- 只打開 Releases 網頁：不必處理安裝，但不符合「可以直接下載安裝」的需求。
- 定期自動檢查：違反「不連網路」的預設，不採用。

## 驗收

單元測試涵蓋版本比較、Release 解析與附件選取、雜湊格式與核對、沒有正式版／同版／新版／網路錯誤／缺雜湊／內容被竄改的狀態。實際下載、掛載與換新須在第一個附 dmg 的 Release 發佈後，以舊版實機升級驗收。
