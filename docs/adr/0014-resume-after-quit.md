# 保存暫停階段，重新開啟由使用者決定接續

2026-11-01 決定：正常退出保存目前已開始階段的暫停進度，執行期間於關鍵操作及每五秒檢查點保存；重新開啟時先顯示最後成功保存的階段、時間與分類，讓使用者選擇繼續或捨棄。退出本身不表示按下完成，超時階段也不自動確立完成。

本決策取代 ADR-0002 的「退出即取消」、ADR-0006 的「超時退出即記錄完成」，及 ADR-0007、ADR-0009 中對應的退出／取消退出規則；其餘真實時間倒數、睡眠／鎖定處理、開始日期歸日、資料相容性與升級原則維持。

- 保存原定階段長度、首次開始時刻、可為負的剩餘秒數、本次分類與長休息間隔進度；專注、短休息與長休息採同一規則。
- 離線與等待恢復選擇的時間不推進進度。選擇繼續才從保存點接續，且不重播先前到點的提醒。App 還在執行時的睡眠與鎖定不屬於退出。
- 捨棄只清除未完成階段，回到一般未開始的專注；保留已完成紀錄、分類與設定。
- 已按完成的五秒暫存仍在退出時確立，復原期限不跨啟動延長；嘗試退出但取消時，不完成當前階段或跳至下一段。
- SQLite 版本 3 新增單一恢復階段的資料表，沿用既有交易遷移與升級前備份。未知版本／載入失敗不得被新計時覆蓋；保存失敗提示重試，退出前可留下或明確放棄。
- 跨啟動的保存格式獨立於視窗與動畫，計時決策由 AppModel 協調，儲存模組處理持久化，所有操作入口共用恢復決策。檢查點沿用獨立模型排程，不依賴可見介面；意外中斷僅保證使用最近成功點，系統延遲或保存失敗可讓落差超過平常五秒週期。

## Considered Options

- 繼續沿原結束時刻倒數：會把 App 關閉期間誤算成投入，違反接續暫停進度的用途。
- 重開立即自動接續：使用者尚未準備好，且自動開始設定不能代表對上次未完成階段的選擇。
- 退出超時直接完成：會使退出與完成具有相同副作用，使用者不能保留進度稍後接續。

## 回滾限制

升級成功後舊 App 可能拒讀新版資料；回退執行檔不等於資料回滾。若需回退，先保留完整現行資料及升級後新增紀錄，再規劃還原，不能直接以舊備份覆蓋現行資料。
