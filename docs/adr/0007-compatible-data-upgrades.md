# 更新時自動遷移資料，維持既有資料相容性

Ripen 更新後首次啟動必須自動找到並載入既有設定與完成的專注，不要求使用者選檔或手動匯入。2026-10-28 確認以下相容性與失敗處理原則，並採用 SQLite 儲存完成的專注、保留 UserDefaults 設定。

## 已確認的決策

- 資料結構可新增欄位、資料表與索引；既有欄位不刪除、不改名、不改型別或語意。新增欄位須允許空值或有合理預設值，使舊資料仍可解讀。
- 新版必須能讀取所有已發佈舊版的資料，包括跳過中間版本直接更新。不承諾舊版能讀取新版資料；具備版本檢查能力的版本遇到不支援的資料版本時，須停止寫入並提示，禁止清空重建。
- 自動遷移須保留原資料，失敗時回滾；成功標記須與遷移資料一併提交，重新啟動不得重複搬移。
- 載入失敗須顯示錯誤，不能將統計呈現為正常的零筆紀錄。
- 寫入失敗時，計時仍可使用；明確顯示尚未儲存，保留本次執行中待重試的紀錄並提供重試。關閉 App 將失去未儲存紀錄時，須先提示使用者。
- 保留首次搬移的原始 JSON，以及最近一次成功升級前的完整資料庫備份。只在資料結構升級前備份，新備份成功後才替換上一份；此機制供升級恢復使用，不構成日常資料備份。
- 舊資料存在無法解讀的紀錄時，整批停止遷移並保留原檔，顯示錯誤與重試入口，不自動跳過或捏造內容。舊版缺少後來新增的欄位屬於正常版本差異，由遷移規則處理。部分資料復原須另行設計與決策，不納入本次實作。

## 儲存方案

以 SQLite 儲存完成的專注，透過明確版本與交易式遷移維護資料結構；首次自動搬移既有 JSON，設定延續 UserDefaults。

## 實作契約

1. 完成的專注改存於 Application Support/Ripen 內的 SQLite 資料庫，既有設定維持 UserDefaults 的 key、型別與語意。儲存模組負責版本檢查、遷移、備份與逐筆寫入；計時及統計公式維持原行為。
2. 初始資料表包含穩定紀錄識別碼、開始時刻與實際時長；明訂時間基準、秒數單位與排序規則，保留既有資料精度、順序及重複紀錄，不預建尚無需求的欄位。資料結構版本獨立於 App 版本。
3. 啟動時先開啟資料庫並檢查版本，再依序執行所需遷移。首次搬移 JSON 時，完整驗證資料後，在同一交易內匯入紀錄並寫入成功標記；中斷或失敗不得留下已完成的標記。既有 SQLite 優先，成功匯入後不再從保留的 JSON 重新匯入。
4. 用資料庫備份機制建立可還原的完整備份，不能假定複製單一資料庫檔就包含所有已提交資料。備份失敗須停止升級；資料庫損壞時不以空資料庫取代，也不自動從較舊的 JSON 重建。
5. 將載入失敗、遷移失敗與尚未儲存呈現為可見狀態；提供重試，並避免重試造成重複紀錄。關閉時若有未保存紀錄，接上退出前提示流程。退出前若有超時階段，先完成該階段；取消退出後停在下一段起點，不自動開始（2026-10-28 決定）。
6. 驗收涵蓋全新安裝、舊 JSON 自動搬移及重啟不重複、重複紀錄保留、跨版本升級、新增欄位後讀取舊資料、未知資料版本拒寫、異常舊資料整批拒絕、備份及遷移失敗後重試、寫入失敗後重試與退出提示。歷史格式樣本固定為測試資料，並執行完整回歸測試。

## 已固定的初始格式

- SQLite 的 application_id 為 0x52504E31，user_version 為 1。版本 1 的提交同時代表原始 JSON 已完整處理。
- 紀錄使用 UUID 識別碼、依完成順序遞增的整數鍵、2001-01-01 UTC 起算的 Double 秒數開始時刻，以及 Double 秒數實際時長。相同內容不去重。
- 使用獨立狀態檔區分初始化中與已啟用，以便中斷後重試，並避免現行資料庫遺失時無聲回退原始 JSON。
- 升級前備份先寫到待提交檔，全部版本遷移在單一交易成功後才取代上一份備份；若提交後中斷，下次啟動完成備份提升。備份轉為不依賴 WAL 的獨立檔案，關閉連線後才更名。

## 回滾限制

遷移失敗須回滾本次交易並保留來源；成功升級後若需還原，使用升級前備份，但須明確處理升級後新增紀錄，不能直接覆蓋而遺失資料。首次切換 SQLite 後，目前的 JSON 版仍無法讀取新產生的紀錄，因此回退 App 執行檔不等同資料回滾。

## Considered Options

- 限制只能新增欄位：獨立的新資料種類會被迫塞入既有表格，因此也允許新增資料表與索引。
- 承諾任意降版皆能讀寫最新資料：會要求舊程式理解未來格式；目前 JSON 版無法讀取遷移後新增的 SQLite 紀錄，保留原 JSON 亦不構成完整降版支援。
- 儲存失敗只寫日誌：使用者可能將記憶體中的紀錄誤認為已保存，因此必須提供可見狀態與重試。
